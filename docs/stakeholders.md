# Стейкхолдеры

## Список

| Стейкхолдер | Роль | Влияние | Интерес | Стратегия |
|-------------|------|---------|---------|-----------|
| Руководитель команды (директор) | Заказчик, пользователь | Высокое | Высокий | Управлять плотно: интервью, демо каждую неделю |
| Разработчик ИР | Команда | Высокое | Высокий | Управлять плотно |
| Руководитель практики (преподаватель) | Контроль, приёмка | Высокое | Средний | Держать в курсе: защиты по неделям, теги в Git |
| Участник команды | Пользователь | Низкое | Высокий | Информировать: опросы, бета-тест |
| Владелец аккаунта | Пользователь | Низкое | Высокий | Информировать |
| Telegram (платформа) | Платформа, правила ToS | Высокое | Низкий | Удовлетворять: соблюдать лимиты и ToS |
| LLM-провайдеры (OpenAI, Gemini, Groq, GigaChat) | Партнёры, поставщики API | Высокое | Низкий | Удовлетворять: лимиты, ключи, фолбэк |
| YouGile, МТС Линк | Партнёры, интеграции | Среднее | Низкий | Наблюдать: изменения API |
| Регулятор (152-ФЗ) | Требования к ПДн | Высокое | Низкий | Наблюдать: мониторинг законодательства |

## Карта стейкхолдеров (влияние × интерес)

| | Низкий интерес | Высокий интерес |
|---|---|---|
| **Высокое влияние** | **Удовлетворять:** Telegram, LLM-провайдеры, регулятор | **Управлять плотно:** директор, разработчик, руководитель практики |
| **Низкое влияние** | **Наблюдать:** YouGile, МТС Линк | **Информировать:** участник команды, владелец аккаунта |

## Вопросы для интервью (с руководителем команды)

1. Расскажите, как сейчас ставятся задачи в команде — где и в каком виде?
2. Сколько задач в день появляется в чате и сколько из них доходит до доски?
3. Как фиксируются итоги встреч? Сколько времени уходит на протокол?
4. Как вы узнаёте, что у участника проблема или он перегружен?
5. Как проходит стендап и что в нём не устраивает?
6. Что чаще всего идёт не так с задачами: сроки, исполнитель, потеря?
7. Какие действия бот ни в коем случае не должен делать без вашего подтверждения?
8. Какие отчёты вы хотели бы получать и с какой периодичностью?

## Результаты интервью (ролевая игра: преподаватель — руководитель команды)

**Что узнали:**
- «Половина задач остаётся в чате: кто-то написал “ок”, а на доске пусто».
- «После встречи задачи из протокола часто неправильные — ИИ путает исполнителя, хочу поправить перед отправкой».
- «Все задачи без колонки падают куда попало — нужна колонка по умолчанию».
- «Для нашей команды “критичный блокер — 1 час” слишком жёстко, хочу настраивать пороги».
- «Бот не должен ничего писать людям от моего имени без подтверждения».

**Что уточнили:**
- FR-07.1 — колонка по умолчанию для новых задач.
- FR-09.1 — редактирование задач из встречи перед отправкой на доску.
- FR-11.1 — настраиваемые пороги эскалации блокеров.
- Подтверждение действий, видимых другим, закреплено как NFR-10 (Must).
