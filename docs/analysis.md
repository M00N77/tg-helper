# Анализ предметной области

## 1. Описание ПрО

Предметная область — **командная коммуникация и управление задачами небольших IT-команд (3–15 человек), которые работают в Telegram**.

В таких командах Telegram де-факто становится основным рабочим инструментом: в нём ставят задачи, договариваются о сроках, проводят созвоны, отправляют голосовые и файлы. При этом формальные инструменты (канбан-доска YouGile, видеосвязь МТС Линк / Jitsi, календарь) живут отдельно, и информация между ними переносится вручную.

Ключевые объекты ПрО: **пользователь**, **команда**, **участник команды** (с ролью), **чат/контакт**, **сообщение** (текст, голос, документ), **обещание** (договорённость со сроком), **задача** на канбан-доске, **встреча** и её запись, **стендап**, **блокер**, **напоминание**, **дайджест**.

Ключевые процессы: переписка и договорённости в чатах; постановка задач; проведение встреч и фиксация итогов; ежедневные стендапы; контроль сроков; оценка состояния команды (нагрузка, настроение, риски срыва).

Информационный ресурс **TelegramHelper** — слой автоматизации поверх Telegram-аккаунта: control-бот (aiogram) принимает команды, свободный текст и голос, а userbot (Telethon) читает переписку владельца, чтобы извлекать обещания, делать саммари и поиск. LLM-агент превращает фразу на обычном языке («напомни завтра в 18:00 позвонить Оле») в действие системы.

## 2. Границы ПрО

| Входит | Не входит |
|--------|-----------|
| Личные и групповые чаты Telegram владельца и команды | Другие мессенджеры (WhatsApp, Slack, VK) |
| Команды, роли (директор / участник), приглашения | Кадровый учёт, зарплаты, табели для бухгалтерии |
| Задачи на доске YouGile (создание, просмотр, перенос, закрытие) | Собственная канбан-доска с нуля, диаграммы Ганта |
| Встречи: создание комнаты, транскрипция записи, саммари, задачи | Собственный видеосервер, хранение видеоархива |
| Обещания из переписки, напоминания, дайджесты | Полноценный CRM (сделки, воронки продаж) |
| Стендапы, блокеры, пульс-опросы, анализ тональности | Медицинская/психологическая диагностика сотрудников |
| Поиск по переписке (SQL + векторный), саммари чатов | Публичный веб-интерфейс и мобильное приложение |
| Шифрование секретов, RBAC, подтверждение действий | Биллинг и платные подписки |

## 4. Бизнес-процессы «AS IS»

### Процесс 1: Постановка задачи в чате
- **Участники:** руководитель (директор), исполнитель.
- **Шаги:** руководитель пишет задачу в общий чат → исполнитель отвечает «ок» → кто-то вручную переносит задачу на доску YouGile (или не переносит).
- **Проблемы:** задачи теряются в потоке сообщений; на доске нет половины задач; срок фиксируется словами («к пятнице») и не контролируется.

### Процесс 2: Встреча и фиксация итогов
- **Участники:** команда, ведущий встречи.
- **Шаги:** создать ссылку на созвон → провести встречу → кто-то пишет протокол по памяти → задачи из протокола вручную заводятся на доску.
- **Проблемы:** протокол пишут не всегда; 30–60 мин ручной работы после встречи; договорённости «кто что делает» теряются.

### Процесс 3: Ежедневный стендап
- **Участники:** участники команды, руководитель.
- **Шаги:** руководитель утром напоминает в чат → участники пишут «что сделал / что планирую / что мешает» в свободной форме → руководитель читает и вручную выписывает блокеры.
- **Проблемы:** нет единого формата; блокеры не эскалируются; без напоминания часть людей не отвечает.

### Процесс 4: Контроль договорённостей в личной переписке
- **Участники:** пользователь, его собеседники.
- **Шаги:** в личных чатах человек обещает «скину завтра», «созвонимся в 8» → держит это в голове или в заметках.
- **Проблемы:** обещания забываются; найти «на чём мы остановились» в длинном чате долго; ответы на важные сообщения откладываются.

### Процесс 5: Оценка состояния команды
- **Участники:** руководитель.
- **Шаги:** руководитель «чувствует» настроение по переписке, спрашивает лично.
- **Проблемы:** выгорание и конфликты замечают поздно; нет объективных данных (опросов, статистики).

## 5. Анализ аналогов

| Аналог | ЦА | Функции | Сильные | Слабые | Монетизация |
|--------|----|---------|---------|--------|-------------|
| **YouGile + Telegram-бот уведомлений** | Команды РФ | Канбан, уведомления о задачах в Telegram | Российский сервис, бесплатный тариф, удобная доска | Бот только уведомляет — задачу текстом/голосом из чата не создать; нет встреч и стендапов | Freemium |
| **Яндекс Трекер** | Средние и крупные компании | Задачи, очереди, интеграция с Яндекс 360 | Мощная настройка процессов | Тяжёлый для маленькой команды; живёт вне Telegram | Подписка |
| **Geekbot / Standuply** | IT-команды в Slack | Асинхронные стендапы и опросы | Готовые сценарии стендапов, отчёты | Ориентированы на Slack/Teams, англоязычные; нет задач и встреч | Подписка за пользователя |
| **Ассистенты встреч (Otter.ai, Яндекс Телемост с конспектом)** | Все, кто много созванивается | Запись, транскрипция, конспект | Качественная транскрипция | Задачи не попадают на доску автоматически; не связаны с чатом команды | Freemium / подписка |

**Вывод:** аналоги закрывают отдельные куски (доска, стендапы, конспект встречи), но ни один не объединяет **переписку + задачи + встречи + стендапы в одном Telegram-интерфейсе на естественном языке**. Это и есть ниша TelegramHelper.
